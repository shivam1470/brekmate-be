# Integration with prepared OpenTofu

Nothing here applies AWS changes. The existing infrastructure does not yet pass the new application settings or create a delivery OTP pepper container. The backend therefore intentionally fails startup until its required runtime configuration is supplied.

1. Review `backend-runtime.patch` against the previously prepared `brekmate-infra`. It adds a `delivery-otp` Secrets Manager container, grants access through the existing exact-secret-ARN list, exports that ARN, and merges a non-secret `application_environment` map into Lambda's environment. It also prevents overriding reserved identity/table bindings. No secret values are placed in the patch or IaC state. The existing `PAYMENT_SECRET_ARNS` list will contain all secret containers; payment code is not implemented and does not consume it.
2. In the infra checkout, run `git apply --check /path/to/brekmate-be/integration/backend-runtime.patch` then apply the reviewed patch. It changes storage/runtime modules plus staging/production inputs. Run the IaC tests, format/schema checks and review a fresh plan locally. Earlier provider execution was blocked by this environment's socket restrictions; schema/plan validation is still required.
3. Set `application_environment` using `application.example.tfvars.json` as a template. Replace the intentionally invalid location placeholders. Set actual venue hours/duration/buffer only after approval. Orders and booking confirmations remain disabled by default. Approval flags are explicit business review gates, not instructions to bypass missing implementations.
4. Through an approved secret-provisioning workflow, put JSON `{"pepper":"<at least 32 cryptographically random characters>"}` in the delivery OTP secret. Do not paste real credentials into chat, source files, Terraform variables or Drive. The application reads it from Secrets Manager on cold start. Secret rotation needs coordination: existing 30-minute OTPs will be invalidated after pepper replacement.
5. Build using `npm run package`. Point `artifact_path` at the absolute path of `artifacts/brekmate-lambda.zip`; handler `index.handler`, runtime `nodejs24.x`, architecture `arm64`. Do not enable the optional worker; there is no worker artifact in this backend baseline.
6. Merge `api_routes` from `api-routes.tfvars.json`. Shared customer/staff routes use gateway audience `public` **only at the transport layer**: the Lambda still requires and cryptographically verifies an access token on every route except `/health`. Separate issuers cannot both be verified by one gateway JWT authorizer. Do not apply a blanket rule interpreting `public` as permission to bypass application authentication, and do not add a wildcard route. Customer-only/staff-only routes retain gateway JWT verification plus application verification.
7. Configure explicit staff HTTPS CORS origins in the infrastructure. The API does not implement a wildcard CORS fallback. Native React Native requests do not require browser CORS.
8. Keep backend deployment disabled until boundaries, cost assumptions, secrets, identities, alarms, release gates and live-service tests are reviewed. No production deployment has been executed from this project.

Required environment: `ENVIRONMENT_NAME` (`brekmate-staging` or `brekmate-production`), `CORE_TABLE`, `LEDGER_TABLE`, `OPERATIONS_TABLE`, `CUSTOMER_ISSUER`, `STAFF_ISSUER`, `CUSTOMER_CLIENT_ID`, `STAFF_CLIENT_ID`, `OTP_SECRET_ARN`, actual outlet latitude/longitude. Additional settings and defaults are defined in `src/config.ts`. Local/test mode overrides are rejected by the Lambda entry point.

The patch adds a Secrets Manager secret, which can incur charges. This implementation and AWS free-tier assumptions do not guarantee a zero cloud bill. No prices or cloud spend have been incurred or estimated as zero by this backend build.
