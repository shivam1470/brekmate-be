# Production gates and remaining backend work

Status: development baseline. These gates are not waived by the passing pricing suite. No claim of complete scenario coverage or 100% production readiness is made.

## Policy decisions that currently block enabling live orders

1. Tax calculation and invoice policy. Current arithmetic is explicitly tax-free and coupon-free; enabling orders requires `ZERO_TAX_POLICY_APPROVED=true` after business review. If taxes apply, implement them instead of setting this flag.
2. Fractional reward paise are rounded down. This is a proposal and requires explicit approval via `REWARD_ROUNDING_POLICY_APPROVED=true` or a corresponding implementation change.
3. Referral eligibility currently binds to the first **created** order. A cancelled/rejected first order does not make a later order eligible. This conservative proposed rule requires `FIRST_ORDER_POLICY_APPROVED=true` or replacement with the approved rule.
4. Full/partial refunds, spent reward reversal, post-preparation cancellation, coupons and discounts are not implemented. Do not open a public paid ordering service until safe refund/reconciliation procedures exist.
5. Booking duration, opening hours, buffer, capacity and promotion inclusions/dates need approval. The venue/camera are free and no minimum food order is enforced. Decoration currently reports that the introductory offer must be confirmed by staff; no unapproved date or assistance price is invented.

## What local evidence establishes

The backend tests exercise arithmetic, validations, business transitions, wallet/referral flows, OTP attempts, stock/reward concurrency, booking slot collisions, application HTTP behavior and storage command construction. They use an in-memory database and injected fixture identities. JWT claim tests do not replace cryptographic/JWKS tests against configured pools.

The previous quality workspace's 37,296 vectors call the actual bundled pricing code: 36,864 generated basket combinations plus 432 pricing boundaries. They are arithmetic/fixture checks, not 37,296 independent native E2E scenarios. Their proposed rounding rule still needs approval before those vectors can count as release acceptance evidence.
